NNN SECURITY TEST WORKBENCH

Observe card security behavior, without losing control.

NNN is a cross-platform GUI for authorized NFC/card read-write security testing in controlled real environments and an offline synthetic-card laboratory.

View sourceRead design notes

Designed for bounded, observable testing

DESIGN LOGIC

A narrow boundary between GUI, readers, workflows, and evidence.

01

GUI boundary

Wails bindings expose serializable services and task events; the GUI never owns native reader handles.

02

Reader boundary

Reader access is serialized through device management and separated from workbench and reporting logic.

03

Write safety

Preflight checks, authentication, block ordering, card identity checks, and read-back verification guard writes.

04

Observable tasks

Long-running work emits cancellable progress, phases, logs, and structured results for review.

RUNTIME MECHANISM

From a selected reader to a testable result.

Scan facts are captured first. Read/write workflows then operate through the reader abstraction, while the workbench tracks known bytes, edits, access bits, and validation warnings. Recovery and audit operations run as tasks and report through the same event stream used by the GUI.

1 · Prepare

Select a validated reader profile and confirm the authorized test scope.

2 · Operate

Authenticate, read, edit, dump, restore, or validate the selected test card.

3 · Verify

Check structure, card identity, counters, access controls, and read-back results.

4 · Report

Preserve progress, logs, results, and sanitized evidence for regression analysis.

PRIMARY USE

Authorized real-environment read-write attack and defense testing.

NNN is designed for security teams and developers testing cards and access-control systems they own or are explicitly authorized to assess. Typical targets include authentication boundaries, replay and stale-state handling, write safety, recovery failure containment, and clone-detection controls. It is not a tool for unauthorized access, credential duplication, or bypassing a third party’s system.

OFFLINE VIRTUAL CARD LAB

Reproduce mechanics without a reader or real card.

The Virtual Card Lab uses synthetic data only. Its bounded audit demonstrates weak-secret risk; its static-clone simulation demonstrates why a copied UID and memory image should fail dynamic authentication and counter checks. The GUI shows live progress and logs, while hardware, network, real dumps, and real-card protocols remain disabled.
