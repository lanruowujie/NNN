# NFCX native runtime layout

Native runtime files are generated by the pinned toolchain scripts on native
GitHub Actions runners and are not committed to Git. The release stage produces
the same logical contents for `darwin-arm64`, `windows-amd64`, and
`linux-amd64`; executable and library suffixes follow each platform.

```text
runtime/
  darwin-arm64/
    libnfc.6.dylib
    libnfc.dylib -> libnfc.6.dylib
    source.lock
    mfoc
    mfoc.sha256
    mfoc-source.lock
    mfcuk
    mfcuk.sha256
    mfcuk-source.lock
    mfoc-hardnested
    mfoc-hardnested.sha256
    mfoc-hardnested-source.lock
    nfc-mfsetuid
    nfc-mfsetuid.sha256
    patches/
      0001-add-nfcx-machine-result.patch
    LICENSES/
      libnfc-COPYING.txt
      mfoc-COPYING.txt
      mfcuk-COPYING.txt
      mfoc-hardnested-COPYING.txt
      nfc-mfsetuid-BSD-2-Clause.txt
  linux-amd64/
    libnfc.so.6.0.0
    libnfc.so.6 -> libnfc.so.6.0.0
    mfoc
    mfcuk
    mfoc-hardnested
    nfc-mfsetuid
    ...metadata and licenses...
  windows-amd64/
    libnfc-6.dll
    mfoc.exe
    mfcuk.exe
    mfoc-hardnested.exe
    nfc-mfsetuid.exe
    liblzma-*.dll
    ...metadata and licenses...
```

The unversioned symlink is for development linking. Packaged macOS applications
load the versioned library through `@rpath`; Linux uses `$ORIGIN`; Windows keeps
the DLL and executables in the private portable application directory because
the DLL loader runs before Go startup. Development headers and pkg-config
metadata are generated separately under `build/toolchain/<os>-<arch>/sdk`.

Every packaged runtime contains `manifest.json`, per-file SHA-256 values,
component source identities, patches, and native/Go dependency licenses.

The fixed libnfc build also packages `nfc-mfsetuid` for the protected Gen1A
UID fallback. It is invoked only after the in-process CUID/Gen2 write leaves
the old UID unchanged, and NFCX still performs its own full block 0 readback.

External engines use the same platform directory. NFCX resolves fixed logical
engine names inside this directory; the GUI cannot provide an executable path.
Release packages bundle pinned, licensed engine builds instead of downloading
them at runtime.

Build the pinned MFOC 0.10.7 runtime against the existing libnfc SDK with
`make mfoc-build`. Its source identity, binary hash and GPL license are copied
alongside the generated runtime.

Build the pinned MFCUK 0.3.8 runtime with `make mfcuk-build`. Its source lock,
GPL license and NFCX machine-result patch are copied alongside the executable.

Build the pinned MFOC-Hardnested 0.10.9 runtime with `make hardnested-build`.
It is linked against the same libnfc SDK, while macOS uses the system liblzma.
Its exact upstream commit, source checksum and GPL license are copied alongside
the executable.

For specification 08 development and manual acceptance, build the local fake
engine with:

```sh
make external-engine-fixture
```

This adds `nfcx-fake-engine` (or `.exe`) to the current platform runtime and
reveals the GUI's “引擎框架自检” button. The fixture is ignored by Git and must
not be included in release packages.
