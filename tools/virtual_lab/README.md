# NNN 虚拟卡安全实验室

这是一个**完全离线、合成数据、教学用途**的虚拟卡实验。它用于观察弱口令、挑战响应、静态 dump 与动态认证之间的差异，不实现真实卡片破解或真实卡片克隆。

## 实验内容

- 创建一张内存内容可见、认证密钥不导出的虚拟卡；
- 使用固定的小型候选列表进行**受限口令审计**，上限为 64 次尝试；
- 导出仅含 UID、内存和计数器的静态快照；
- 将快照装载为“静态克隆”，验证它可以伪造静态内容，但无法通过挑战响应；
- 检查 UID 冲突、静态指纹一致、计数器复用和动态认证失败等克隆告警信号。

## 运行

```bash
cd tools/virtual_lab
python3 virtual_card_lab.py --demo
python3 virtual_card_lab.py --crack   # 一键受限口令审计，仅合成卡
python3 virtual_card_lab.py --clone   # 一键静态克隆模拟，随后运行检测
python3 -m unittest -v test_virtual_card_lab.py
```

`--crack` 不是针对真实目标的无限密码爆破，而是对程序内置合成卡执行最多 64 次的固定候选审计；`--clone` 只在内存中复制静态快照，并立即验证动态认证失败。两个入口均不能接收读卡器、真实 dump、网络地址或外部命令参数。

输出会明确标注：

- `hardware: false`
- `network: false`
- `real_card_protocol: false`
- `secret_exported: false`
- `max_audit_attempts: 64`

## 运行机理

```text
候选口令
   │（最多 64 次）
   ▼
PBKDF2-HMAC-SHA256 派生候选秘密
   │
   ▼
HMAC(challenge) ──比较── 虚拟卡内部秘密生成的证明

静态快照 ──复制──> 静态克隆
                       │
                       └──没有动态秘密，挑战响应必然失败
```

该协议是教学模型，不是 NFC 或任何真实卡片协议的实现。它没有 PN532、libnfc、串口、PC/SC、外部恢复工具、真实 dump 输入或网络目标入口。

## 可观察的防御要点

1. **不要把静态内存当作全部身份凭证**：UID 和数据相同不代表拥有动态秘密。
2. **挑战必须一次性使用**：重复或未由卡片签发的挑战应被拒绝。
3. **计数器应单调递增并绑定设备状态**：静态克隆无法同步真实计数器。
4. **审计接口必须有限速和封顶**：实验中的 64 次上限用于验证防护逻辑，不代表真实密码学强度。
5. **密钥不应进入 dump**：快照只包含静态字段，认证秘密始终留在虚拟卡对象内部。

## 明确不提供

- 对真实卡片、读卡器、NFC 帧或第三方系统的操作；
- 无限字典、远程爆破、GPU/并行破解或未知密钥恢复；
- 认证绕过、后门命令、UID 修改或真实整卡写入；
- 将快照写入实体卡或生成可用的真实卡副本。
