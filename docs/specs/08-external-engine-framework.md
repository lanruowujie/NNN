# 规格 08：外部引擎任务框架

## 目标

建立与具体破解算法无关的外部程序执行框架，正确解决设备独占、路径、环境、日志、取消、超时和结果校验。

## 前置条件

- 规格 07 已验收。

## 范围

- 定义 `AttackEngine`、`AttackRequest`、`AttackEvent`、`AttackResult`。
- 定义平台运行时和可执行文件定位规则。
- 使用 `exec.CommandContext` 启动子进程，不经过 shell。
- 实时读取 stdout/stderr，处理长行和分片。
- 支持取消、超时和进程退出码。
- 实现主进程 libnfc 释放设备、外部程序运行、设备重开的事务流程。
- 为每次任务创建独立临时目录。
- 通过 fixture fake engine 完成无硬件测试。
- 在 GUI 中显示任务状态、日志和取消按钮。

## 不在本阶段实现

- 真正的 mfoc/mfcuk 参数；
- 根据自然语言日志猜测复杂进度；
- 同一设备并行运行多个引擎；
- 自动下载远程二进制。

## 状态模型

外部任务至少经过：

```text
queued
releasing_device
starting
running
cancelling
validating_result
reopening_device
succeeded | failed | cancelled
```

无论在哪一步失败，都必须尝试恢复设备到可用状态。恢复失败时应保留原始任务结果，同时单独报告设备恢复错误。

## 安全要求

- 可执行文件必须来自受控 runtime 目录；
- 参数使用数组传入；
- 用户提供的路径不能成为可执行程序路径；
- 临时文件名由程序生成；
- 不修改系统级 libnfc 配置；
- 环境变量只作用于子进程；
- 发布构建可以校验引擎文件哈希；
- 当前工作流不向外部引擎提供网络参数或自动下载能力；引擎使用随应用 bundle 的固定离线版本。本阶段不增加操作系统级网络封锁，也不限制 NFCX 未来的遥测等联网功能。

## 自动化测试

- 参数中包含空格和非 ASCII 路径；
- stdout/stderr 并发大量输出不会死锁；
- 取消能终止 fake engine；
- 超时返回独立错误；
- 非零退出码保留日志；
- 设备在成功、失败、取消时都尝试重开；
- 临时目录清理和保留诊断策略；
- GUI 不会收到取消后的伪成功事件。

## 验收标准

- [x] fake engine 可以从 GUI 启动并输出实时日志。
- [x] 取消和超时真实终止进程。
- [x] 外部任务运行时普通 NFC 操作被标记为 busy。
- [x] 任务结束后读卡器自动恢复。
- [x] 路径中包含空格时仍能运行。
- [x] 无任何 shell 命令拼接。
- [x] 失败诊断包含退出码、工具版本和必要日志。
