# 规格 04：设备管理与寻卡

## 目标

完成从 GUI 选择读卡器、建立连接、持续检测卡片到显示卡片信息的第一条真实纵向工作流。

## 前置条件

- 规格 03 已验收。

## 范围

- 实现 `DeviceManager`，统一管理选中设备、句柄和互斥访问。
- 枚举并显示 libnfc 设备名称和 connstring。
- 支持手动输入 connstring，覆盖无法自动发现的 PN532 UART。
- 实现连接、断开、刷新和状态事件。
- 后台寻卡但不阻塞 GUI。
- 识别卡片出现、保持、移除和更换。
- 显示 UID、ATQA、SAK、UID 长度和推断卡型。
- 将错误分类为无卡、忙、超时、权限、设备断开和不支持。

## 不在本阶段实现

- 卡片认证和内容读取；
- 自动重写系统权限；
- 外部破解任务；
- 把仅凭 SAK 的推断当成绝对卡型结论。

## 实现要求

设备状态至少包含：

```text
disconnected
connecting
ready
polling
busy
recovering
error
```

寻卡循环必须有明确生命周期：窗口关闭、用户断开、任务切换和 context 取消都会终止循环。不得每次轮询都重新初始化整个 libnfc context。

相同 UID 连续被检测到时只更新“仍在场”，不要无限向 GUI 发送重复卡片事件。UID 或卡片选择参数变化时，应发送“旧卡移除”和“新卡出现”。

自动重连采用有限退避；权限错误和配置错误不应无限重试。

## 自动化测试

- DeviceManager 串行化并发操作；
- 重复出现同一卡片不会产生事件风暴；
- 卡片移除、更换的事件顺序正确；
- 设备拔出后进入 error/recovering；
- 取消 context 后轮询 goroutine 退出；
- 手动 connstring 不被日志或配置意外改写。

## 手工验收

1. 启动 GUI，选择 PN532 UART connstring；
2. 连接成功并显示设备状态；
3. 放入 Classic 1K 测试卡，显示 UID、ATQA、SAK；
4. 移除卡片，GUI 在合理时间内恢复“无卡”；
5. 更换另一张卡，不重启应用即可更新信息；
6. 拔出并重新插入读卡器，能够手动或自动恢复。

## 验收标准

- [ ] GUI 可以枚举或手动连接 PN532 UART。
- [ ] 主窗口在轮询期间保持响应。
- [ ] 卡片出现、移除和更换状态正确。
- [ ] 不支持或无法判断的卡型会明确标注“未知”。
- [ ] 设备拔出不会导致应用崩溃。
- [ ] 所有后台 goroutine 都可取消。
