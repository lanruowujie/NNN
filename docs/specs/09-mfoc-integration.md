# 规格 09：MFOC Nested 集成

## 目标

在至少已知一把有效 MIFARE Classic 密钥的情况下，通过外部 `mfoc` 执行 Nested 恢复，并将结果安全地导入 NFCX 密钥模型和 dump 工作流。

## 前置条件

- 规格 08 已验收。
- 已固定一个可在当前平台运行、许可证清晰的 mfoc 版本。
- 当前测试读卡器和测试卡确认适用于该 Nested 流程。

## 范围

- 实现 `MFoCEngine` 适配器。
- 检测二进制、依赖库和版本。
- 将选中设备 connstring 传给子进程。
- 传入已验证的已知密钥。
- 指定任务专用输出 dump 文件。
- 将 stdout/stderr 转换为日志和有限进度事件。
- 校验输出文件并提取 sector trailer 中的 Key A/Key B。
- 使用 in-process libnfc 重新验证恢复出的密钥。
- 把已验证结果并入当前工作区，不覆盖用户已有的冲突数据。

## 不在本阶段实现

- 没有任何已知密钥时自动运行 mfcuk；
- Hardnested；
- 对所有检测到的读卡器宣称支持 Nested；
- 单纯根据 mfoc 输出文字把未验证密钥标记为成功。

## 实现要求

启动前必须确认：

- 当前卡片是目标 UID；
- 至少有一把经 NFCX 验证的密钥；
- 读卡器 capability 标记允许尝试 Nested；
- 输出路径位于任务临时目录；
- GUI 已展示仅限授权卡片的提示。

mfoc 成功退出后也必须校验 dump 长度和结构。提取出的每把密钥在导入前都要重新认证对应 sector。验证失败的结果保留在诊断报告中，但不能进入“已验证密钥”集合。

## 自动化测试

- mfoc 参数生成；
- 已知 Key A/Key B 参数选择；
- 成功、非零退出、超时、无输出文件和损坏输出文件；
- 1K dump 密钥提取；
- 与现有密钥冲突时不静默覆盖；
- 重新验证失败时结果降级；
- 示例输出解析不依赖完整行一次到达。

## 手工验收

- 使用专用授权测试卡，预先知道其中一把密钥；
- 从 GUI 启动 MFOC；
- 运行期间显示日志且可取消；
- 完成后恢复设备连接；
- 新密钥经过重新认证并显示在扇区表；
- 使用新密钥成功生成完整或更完整的 dump。

## 验收标准

- [x] 没有已验证密钥时 MFOC 不会误启动。
- [x] MFOC 运行期间设备独占正确。
- [x] 输出 dump 经过结构验证。
- [x] 恢复密钥经过 in-process libnfc 重新验证。
- [x] 取消、失败后读卡器恢复可用。
- [x] GUI 明确区分“工具声称找到”和“NFCX 已验证”。
