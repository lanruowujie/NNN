# 规格 07：密钥扫描与数据工作台 GUI

## 目标

把底层读写能力整理为可日常使用的 GUI：管理密钥、扫描每个扇区、查看和编辑 dump，并清楚表达每个 block 的状态。

## 前置条件

- 规格 06 已验收。

## 范围

- 内置一份来源明确、去重后的常见 Classic 密钥字典。
- 支持添加、删除和导入用户密钥，并将当前全部已知密钥导出为兼容字典。
- 对每个 sector 分别尝试 Key A/Key B。
- 找到密钥后立即验证并记录来源。
- 可取消扫描并保留已经确认的结果。
- 扇区/block 表格、Hex/ASCII 查看和编辑。
- 明确标识 manufacturer block、数据块和 sector trailer。
- GUI 中完成 dump、加载、预检、写入和验证流程。
- 所有可见密钥区域（密钥库、扇区状态、trailer block 和差异预览）均显示完整密钥；普通任务日志不记录密钥值。

## 不在本阶段实现

- Nested/Darkside/Hardnested；
- 在线密钥数据库；
- 解析特定门禁、交通卡或储值业务数据；
- 未经确认直接写 sector trailer。

## 实现要求

密钥模型至少记录：

- 6 字节值；
- 来源：内置、用户输入、文件导入、读取上下文或破解引擎；
- 是否已验证；
- 成功对应的 sector 和 Key A/Key B；
- 首次/最近使用时间可以作为非必需元数据。

扫描顺序应优先复用已知成功密钥，再尝试常见字典，避免对每个 sector 从头重复全部列表。扫描任务要显示当前 sector、key type、已尝试数量和已找到数量，但不在普通日志输出完整密钥。

当前 GUI 的推荐操作顺序统一为“自动恢复密钥 → 自动读取验证 → 保存或编辑”。每次贴卡会话都必须先成功完成统一恢复流程，才启用“读取整卡”和卡片写入类操作；历史验证记录或从 metadata 恢复的密钥可以加速流程，但不会绕过本次卡片的读取验证。

设备连接只使用 libnfc 自动枚举结果，GUI 不提供手动 connstring 输入。桌面窗口必须允许调整大小、最大化和进入系统全屏。

GUI 提供跟随系统、浅色和深色三种主题模式；首次启动默认跟随系统，用户的显式选择在本机持久化。

Hex 编辑器的修改只作用于内存中的工作副本；ASCII 编辑接受最多 16 个 ASCII 字节，不足 16 字节时在尾部自动补 `00`，超过 16 字节或包含非 ASCII 字符时拒绝。用户点击保存或写卡前必须展示 dirty 状态。trailer 或 block 0 的编辑必须触发额外验证和危险提示。“加载”始终可用；“清屏”清空当前内存工作副本；GUI 不再提供“全部还原”按钮。

## 自动化测试

- 字典解析、大小写、空格和重复项；
- 非 12 位十六进制密钥被拒绝；
- 已知成功密钥的优先级；
- 取消扫描后结果保持一致；
- Hex/ASCII 编辑 round trip，以及短 ASCII 输入的 `00` 填充；
- dirty 状态和撤销/重新加载行为；
- 普通任务日志不包含密钥值。

## 手工验收

- 导入包含重复和非法行的字典，GUI 正确报告；
- 对测试卡扫描并显示每个 sector 的 Key A/Key B 状态；
- 中途取消后仍能使用已找到密钥读取相应扇区；
- 修改普通数据块，预览差异并写回验证；
- 修改 trailer 时出现明确的 access bits 解释和确认；
- 重新加载文件后 dirty 状态清除。

## 验收标准

- [x] 用户能在 GUI 内完成已知密钥扫描和整卡读取。
- [x] 每个 sector 的 A/B 密钥状态和完整密钥清晰可见。
- [x] 扫描可取消且不会断开或锁死 GUI。
- [x] 编辑器区分 block 类型并保护危险区域。
- [x] 写卡前可以查看差异和预检结果。
- [x] 默认日志不记录密钥值。
