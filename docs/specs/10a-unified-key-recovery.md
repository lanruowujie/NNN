# 规格 10A：统一密钥恢复入口

## 目标

把“扫描已知密钥”和外部恢复工具编排为一个可取消的用户任务。用户只需要选择 `自动恢复密钥`，NFCX 根据已验证结果决定是否运行 Darkside 或 Nested，最后通过实际读取判断卡片是否可用。

## 固定五步

1. 扫描历史记录、用户字典和常见密钥。
2. 没有任何已验证种子密钥时，对支持的 Classic 1K + PN532 UART 运行 Darkside；该阶段上限为 1 小时。
3. 至少有一个扇区具备已验证 Key A 或 Key B、但密钥覆盖仍不完整时运行 Nested。
4. Nested 后仍不完整时检查 Hardnested 能力。可用时运行规格 10B 的 MFOC-Hardnested adapter；不可用或失败时保留已有结果并显示原因。
5. 使用 NFCX 密钥库中的已验证密钥重新逐扇区读取。只有实际读取验证通过的扇区才算可用，结果载入工作台。

步骤可以按条件标记为“跳过”，但 UI 始终显示全部五步。Darkside 与 Nested 运行期间，百分比不可计算时使用不确定进度动画，并持续显示阶段、已用时、剩余超时和原始日志。

## 结果语义

- `complete`：所有扇区通过实际读取验证，可以启用整卡读取。
- `partial`：至少一个扇区可读；有效密钥和已读数据保留，并明确显示未完成步骤及原因。
- `failed`：没有扇区通过读取，或在取得可用结果前发生致命错误。
- 用户取消是独立终态，不弹出“失败”结果；已通过验证的结果仍保留。

## 安全与并发

- 启动前必须确认卡片已获授权。
- 未检测到卡片时，所有 NFC 业务按钮均禁用；检测到受支持的 Classic 卡片后，先只启用“自动恢复密钥”。授权弹窗打开期间，“确认授权并开始”不再受密钥或工作台状态限制；卡片移除或变更时立即关闭弹窗并禁止启动。已有任务仍按全局设备互斥要求禁止并发。
- 统一任务继续使用全局设备锁。外部工具与 in-process libnfc 的释放、重开和复验顺序不变。
- 卡片改变、移除、读卡器恢复失败或上下文取消必须立即终止后续步骤。
- 日志和结果 DTO 不包含完整密钥值。

## 自动化验收

- 常见密钥覆盖完整时跳过 Darkside、Nested 和 Hardnested。
- 部分常见密钥触发 Nested；失败或覆盖不完整后进入 Hardnested。
- 没有种子密钥时进入 MFCUK pipeline，候选复验通过后再进入 Nested。
- Darkside 无有效候选时在第 2 步失败。
- Darkside 转入 Nested 前，第 2 步先变为完成。
- 外部阶段取消能够传播为取消终态。
- 任务事件包含固定步骤、状态与不确定进度标志，且不泄露密钥。

## 手工验收

- 连接 PN532 UART 并放入授权 Classic 1K 卡，主界面出现且可点击 `自动恢复密钥`。
- 确认弹窗明确提示 Darkside 最长 1 小时和 Hardnested 最长 6 小时。
- 运行中五步状态、进度动画、日志和取消按钮持续可见。
- 成功、部分成功或失败后显示结果弹窗；失败信息包含步骤和原因。
- 完整恢复并读取验证后，工作台显示完整 dump，`读取整卡` 可用。
- 完整恢复前，读取、写入修改、恢复备份和修改 UID 均不可用；完整恢复完成后再按工作台完整性、dirty 状态与 UID 卡型能力分别启用。
