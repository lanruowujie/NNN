# 规格 07/10A/11 按钮状态机调整记录

日期：2026-09-13

## 实际完成内容

- NFC 操作改为按本次贴卡会话解锁：无卡时自动恢复密钥、读取卡片、写入修改、恢复备份和修改 UID 全部禁用；检测到受支持的 Classic 卡后，先只启用自动恢复密钥。
- 自动恢复密钥成功后已由既有第五阶段自动读卡并载入工作台，随后启用读取整卡；写入修改、恢复备份和修改 UID 再分别叠加 dirty、完整备份、Classic 1K/4-byte UID、sector 0 密钥等安全条件。
- 卡片移除或换卡会清除本次会话的恢复成功状态。若授权确认窗口仍打开，立即关闭窗口；窗口内的“确认授权并开始”在卡片仍在场时不受工作台或密钥状态限制。
- Block 工作区的“加载”始终可点击，不再受卡片或 NFC 任务状态限制。
- 删除“全部还原”和“引擎框架自检”界面入口；“恢复 Dump 到卡片”统一改为“恢复备份”。
- Block 工作区新增“清屏”，通过新的 Wails binding 清空内存工作副本并广播空工作台快照。点击后先在前端即时清空，再与后端权威状态同步；NFC 任务运行时禁用，避免刚清空又被正在完成的读卡结果覆盖。
- “确认授权并开始”本身就是放弃旧工作副本并执行恢复的确认，不再叠加不稳定的浏览器原生确认框；请求始终携带 `discardDirty=true`，避免前后端 dirty 状态短暂不同步时被后端拒绝。

## 实现过程中遇到的问题

### 历史密钥不能代表本次卡片已经准备完成

旧按钮逻辑仅根据已验证密钥数量解锁读取和写入。加载带 metadata 的备份或命中历史记录后，会在未执行本次卡片读取验证时过早开放操作。现在单独维护本次贴卡会话的恢复完成状态，只在统一恢复结果为 `complete` 时解锁，并在移卡或换卡事件中重置。

### 本地工作区操作与 NFC 状态需要分开

“加载”只操作文件和内存工作副本，不应被无卡或设备忙状态连带禁用。清屏同样不依赖读卡器；清空后保留当前卡片会话的恢复状态，但需要重新读取或加载完整备份后才能执行对应写入。

### WebView 原生确认框造成点击后无反馈

授权弹窗内再次调用 `window.confirm` 在桌面 WebView 中表现不稳定，并且会把一次明确授权拆成两次确认。清屏原先也要等后端 Promise 返回后才更新画面，调用失败或延迟时看起来像没有点击。现在恢复授权不再嵌套原生确认框；清屏先给出即时视觉和日志反馈，失败时恢复后端快照并显示错误。
